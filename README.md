# Audit – protocol amendment demo

A clickable concept demo of a product that sits on top of Veeva systems and carries a protocol amendment through to a signed-off EDC schema update, from three perspectives:

- **Sponsor** (styled after Vault CDMS Studio): review schema options A–D for the amendment, with a pros/cons map and a recommendation, then validate and approve.
- **CRO** (styled after EDC Tools): deploy the new casebook version, roll it out site by site, track tasks and messages.
- **Site** (styled after Site Connect): see what changes, map the new schedule onto participants already in the trial (Transition Plan), and sign off.

Every role can reject a proposal and say what to try instead, ask the assistant questions, and see the audit trail.

## Run it

It is a static site with no build step. Open `index.html` in a browser, or serve the folder:

```sh
python3 -m http.server 8000
```

`render.yaml` deploys it as a Render static site.

## What is real and what is simulated

Real, from public sources:

- Study NCT03235752 (protocol CTJ301UC201): sponsor, enrollment and the 27 site names, from the ClinicalTrials.gov API (`ctgov.js`).
- The protocol PDF in `assets/protocol.pdf`, from ClinicalTrials.gov, and the quotes and page references taken from it.

Simulated for the demo:

- Site staff, subjects, ethics committee dates and rollout status.
- The content of the amendment (protocol v1.0 is not public) and the schema options with their pros and cons.
- The assistant: its suggestions and answers are scripted, not generated by a model.
- The audit trail checksum chain, which is illustrative and not cryptographic.

State lives in memory and resets on reload.

This is an independent concept demo. It is not affiliated with or endorsed by Veeva Systems.
